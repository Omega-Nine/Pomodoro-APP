# Pomodoro App — Decisions

Этот файл хранит принятые архитектурные и продуктовые решения проекта.

Главная цель — не держать все решения в памяти и не переизобретать их
каждый раз при возвращении к проекту.

---

# Project approach

Первая полноценная версия приложения создаётся на Vanilla JavaScript.

Стек первой версии:

- Vite
- HTML
- CSS
- JavaScript
- ES Modules
- Firebase
- Vitest
- библиотека для графиков — выбрать позже

После завершения рабочей Vanilla JS версии планируется миграция интерфейсных
компонентов на React.

Vanilla-версию не удаляем.

Она должна остаться как отдельная законченная версия проекта.

Примерно:

v1.0 — Vanilla JavaScript  
v2.0 — React migration

---

# Development principles

Сначала проектируем данные и поведение системы.

Потом делаем минимальный интерфейс, необходимый для работы логики.

Полноценный дизайн и адаптивная верстка выполняются после основной логики.

Не добавляем функциональность только потому, что её можно добавить.

Дополнительная функция должна:

- заметно улучшать UX;
- либо показывать полезное архитектурное решение;
- при этом не добавлять непропорционально много сложности.

Ориентир:

минимум дополнительной разработки → максимум практической пользы.

---

# Data principles

Не хранить данные, которые можно надежно вычислить из других данных.

Избегать нескольких источников правды.

Например, вместо:

isDeleted: true

используем:

deletedAt: дата

Если:

deletedAt === null

задача не удалена.

Если:

deletedAt !== null

задача находится в корзине.

---

# Task

Основная сущность задачи.

Предварительная структура:

Task

- id
- title
- description / context
- priority
- deadline
- plannedPomodoros
- scheduledFor
- createdAt
- completedAt
- deletedAt

---

## id

Уникальный идентификатор задачи.

Используется для связи задачи с Pomodoro-сессиями.

---

## title

Название задачи.

---

## description / context

Дополнительное описание или контекст задачи.

Название поля окончательно выбрать позже:

description

или

context

---

## priority

Приоритет задачи.

В интерфейсе приоритет может отображаться цветом.

Конкретные значения приоритетов определить позже.

---

## deadline

Крайний срок завершения задачи.

Deadline и scheduledFor — разные понятия.

Пример:

scheduledFor = 5 октября  
deadline = 10 октября

Это означает:

5 октября пользователь планирует работать над задачей,
но закончить её необходимо не позднее 10 октября.

Приложение не должно автоматически изменять deadline без решения пользователя.

---

## plannedPomodoros

Количество Pomodoro, которое пользователь планирует потратить на задачу.

Количество реально выполненных Pomodoro не обязательно хранить непосредственно
в Task.

Его можно вычислить из PomodoroSession.

Это позволяет избежать дублирования данных.

---

## scheduledFor

Дата, на которую пользователь запланировал работу над задачей.

Если:

scheduledFor === null

задача не назначена на конкретный день и находится в общем списке.

Если:

scheduledFor === конкретная дата

задача входит в план на этот день.

Таким образом отдельное поле вроде:

isDaily

не требуется.

---

## createdAt

Дата и время создания задачи.

Созданная задача всегда имеет createdAt.

---

## completedAt

Дата и время завершения задачи.

Пока задача не завершена:

completedAt === null

После завершения:

completedAt === дата завершения

Отдельный status = "completed" не требуется.

---

## deletedAt

Дата и время помещения задачи в корзину.

Пока задача активна:

deletedAt === null

После удаления:

deletedAt === дата удаления

Используется Soft Delete.

Задача физически не удаляется из базы.

---

# No global Task status

Пока решено не хранить единое поле:

status

Причина:

разные состояния задачи можно определить по другим данным.

Например:

completedAt !== null
→ задача завершена

deletedAt !== null
→ задача находится в корзине

scheduledFor === null
→ задача находится в общем списке

scheduledFor !== null
→ задача назначена на определённый день

Состояния:

running
paused
stopped

не принадлежат Task.

Они относятся к Timer / PomodoroSession.

---

# Independent states

completedAt и deletedAt являются независимыми данными.

Задача может сначала быть завершена, а позже удалена.

Например:

completedAt = 5 октября  
deletedAt = 10 октября

Это нормальное состояние.

Удаление задачи не отменяет факт её завершения.

---

# Derived values

Следующие значения пока не хранятся в базе отдельными полями.

---

## isDeleted

Вычисляется:

deletedAt !== null

---

## isCompleted

Вычисляется:

completedAt !== null

---

## isOverdue

Примерная логика:

deadline уже прошёл
+
completedAt === null
=
задача просрочена

Отдельное поле isOverdue хранить не требуется.

---

## isMissed

Примерная логика:

scheduledFor находится в прошлом
+
completedAt === null
+
deletedAt === null
=
пользователь пропустил запланированную задачу

Отдельное поле isMissed хранить не требуется.

---

# Pomodoro Session

Pomodoro-сессия — отдельная сущность.

Она не является частью Task.

Каждая сессия связана с задачей через taskId.

Пример:

Task

id = 15

PomodoroSession

taskId = 15

---

## Preliminary PomodoroSession structure

- id
- taskId
- startedAt
- endedAt / completedAt
- duration
- result

Точная структура ещё не окончательная.

---

## taskId

ID задачи, к которой относится сессия.

Не копируем название и описание Task в каждую PomodoroSession.

Это позволяет избежать ненужного дублирования данных.

---

## result

Сессия должна хранить результат.

Минимально необходимо различать:

success
interrupted

Возможно позже появятся дополнительные значения.

---

# Session history

Храним историю как успешных, так и прерванных Pomodoro.

Хранить только провалы недостаточно.

Например:

2 провала из 100 попыток

и

2 провала из 3 попыток

имеют совершенно разный смысл.

Поэтому отчёт должен учитывать и успехи, и неудачные попытки.

---

# Reports

Исторические данные не должны изменяться из-за последующих действий
пользователя с задачей.

Пример:

В понедельник пользователь выполнил 10 Pomodoro.

Во вторник он отправил задачу в корзину.

Отчёт за понедельник всё равно должен показывать эти 10 Pomodoro.

Удаление Task не удаляет историю выполненной работы.

---

## Report metrics

Хотим разделять минимум два показателя:

1. Фактически потраченное время.
2. Количество Pomodoro-попыток и их результаты.

Например:

Фактическое время: 60 минут

Попытки: 3

Успешные: 2

Прерванные: 1

---

# Session date in reports

Pomodoro относится к дате завершения сессии.

Пример:

начало:

5 октября 23:50

завершение:

6 октября 00:15

Сессия относится к отчёту за 6 октября.

---

# Actual work time

В отчёт должно попадать время, когда пользователь действительно работал.

Пауза не считается рабочим временем.

Пример:

10 минут работа  
20 минут пауза  
5 минут работа

Фактически потрачено:

15 минут

Просто вычислить:

endedAt - startedAt

недостаточно.

Механизм учёта пауз спроектировать позже.

---

# Delete behavior

Используется Soft Delete.

Удалённая задача физически остаётся в базе.

Это позволяет:

- сохранить историю;
- сохранить связь PomodoroSession → Task;
- реализовать корзину;
- восстановить задачу.

---

## Deleted task behavior

Если:

deletedAt !== null

то задача:

- скрывается из обычного списка;
- отображается в корзине;
- не может запускать новый Pomodoro.

---

# Delete active task

Если пользователь пытается удалить задачу с работающим таймером:

1. Показать окно подтверждения.
2. Если пользователь отменяет удаление:
   - ничего не менять;
   - таймер продолжает работать.
3. Если пользователь подтверждает:
   - остановить таймер;
   - сохранить текущую PomodoroSession как interrupted;
   - сохранить реально отработанное время;
   - записать дату в deletedAt;
   - переместить задачу в корзину.

---

# Restore task

При восстановлении:

deletedAt = null

История Pomodoro не изменяется.

Task сохраняет тот же id.

Поэтому существующие PomodoroSession продолжают быть связаны
с восстановленной задачей.

---

# Completed task and scheduledFor

После завершения задачи scheduledFor пока НЕ очищаем.

Причина:

это историческая информация о том,
когда пользователь планировал работать над задачей.

---

# Missed scheduled task

Это небольшое улучшение по сравнению с исходным ТЗ.

Если:

scheduledFor находится в прошлом

и

completedAt === null

и

deletedAt === null

приложение сообщает пользователю,
что запланированная задача не была выполнена.

Пользователь получает три действия:

Продолжить  
Отложить  
Удалить

---

## Continue

Пользователь хочет продолжить работу сегодня.

scheduledFor изменяется:

старая дата → сегодняшняя дата

Deadline автоматически не изменяется.

Priority автоматически не изменяется.

---

## Postpone

Пользователь выбирает новую дату scheduledFor.

Deadline автоматически не изменяется.

---

## Delete

Задача отправляется в корзину.

В deletedAt записывается текущая дата.

Исторические PomodoroSession не удаляются.

---

# Automatic behavior

Приложение не должно самостоятельно:

- повышать priority пропущенной задачи;
- менять deadline;
- удалять задачу;
- считать задачу ненужной.

Важные решения остаются за пользователем.

Приложение только сообщает о ситуации и предлагает действия.

---

# Global / Daily concept

В оригинальном ТЗ существуют Global Task List и Daily Task List.

В нашей версии это можно реализовать через scheduledFor.

scheduledFor === null

→ Global / unscheduled task

scheduledFor === today

→ задача на сегодня

Это позволяет не хранить отдельные флаги Global / Daily.

---

# Timer responsibility

Timer отвечает за текущее состояние отсчёта.

Например:

running
paused
stopped

Task не должна хранить состояние таймера.

Это разделяет ответственность между сущностями.

---

# Statistics after deletion

Удаление задачи влияет на её видимость,
но не влияет на историческую статистику.

Task может быть скрыта из обычного интерфейса,
но её прошлые PomodoroSession продолжают участвовать в Reports.

---

# MVP rules

Сначала реализуем необходимый функционал.

Не добавляем сложную функциональность,
если она не нужна для основной версии.

Отложенные идеи можно хранить отдельно.

---

# Deferred ideas

Пока НЕ реализуем:

- повторяющиеся задачи;
- сложный календарь;
- streak;
- achievements;
- проекты;
- теги;
- автоматическое изменение priority;
- автоматическое изменение deadline;
- сложную систему повторных попыток Task;
- восстановление задачи с выбором нескольких прошлых сессий;
- "начать задачу заново" как отдельный режим.

Эти функции можно рассмотреть после завершения MVP.

# Open questions

## Restore + scheduledFor

Что делать с scheduledFor при восстановлении задачи из корзины?

Варианты:

1. сохранить старую дату;
2. установить scheduledFor = null;
3. спросить пользователя:
   - продолжить сегодня;
   - выбрать другую дату;
   - вернуть в общий список.

Пока решение не принято.
